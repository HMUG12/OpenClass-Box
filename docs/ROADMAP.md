# OpenClass-Box 产品规划

> 定位：**课堂一体机的离线急救箱 + 电教委员的运维平台**。
> 老师一键自救、电教日常维护、专业人员深度排障；对外还能一个网址管整个机房。

---

## 一、产品定位

| 维度 | 说明 |
|---|---|
| 部署环境 | 教室一体机（Windows 10/11），网络受限或不可控，无人值守 |
| 使用者 | 老师（非专业，时间窗口只有上课前几分钟）、电教委员（日常维护）、专业维修人员 |
| 核心价值 | 离线可用 · 免依赖（目标机无需装任何前置组件）· 一键化 · 结论化 |
| 差异化 | 通用工具箱只给数字和进度条；这里要给**结论**和**下一步怎么办** |

## 二、现状（v0.2.4）

### 已完成 · 课堂急救主线

- 一键体检（多维检测 + 建议）、一键修复（DNS / 临时文件 / 音频服务 / 网络重置等，可回滚）
- 磁盘清理、网络诊断、诊断包导出（含系统信息与事件日志）
- 课堂检测：投影拓扑、触摸点数、无线投屏能力、教学软件盘点、还原环境识别
- 学期模式：开学 / 考试 / 假期三套检查清单 + 报告导出
- 兼容性知识库：内置条目 + 按本机环境自动匹配 + 记录经验 + 导出问题报告
- 密码保护：关键页面防学生误改（PBKDF2 散列、失败锁定、闲置自动上锁）

### 已完成 · 运维平台主线

- 机房协同：A 端（服务端）/ B 端（被管理端），批量下发体检 / 修复 / 清理 / 消息 / 文件 / 换壁纸
- 远程电源控制：关机 / 重启 / 睡眠 / 休眠 / 取消关机（默认关闭、延迟执行、二次确认、全程留痕）
- 定时任务：命令 / 脚本 / 程序 + 每天 / 每周 / 一次性 / 开机后
- 手机 Web 控制台：同 WiFi 零安装，实时状态 + 一键体检 + 远程修复
- **A 端远程管理（Web）**：通过内网穿透在教室外管理机房，功能完整（含电源控制）
- **内网穿透套件**：cloudflared / frp / ngrok / 自定义，自动抓公网地址
- 临时传输：局域网聊天与文件互传（房间码 + 可选密码，退出即清空）
- USB 便携急救盘：数据随 U 盘走，插到哪台机器都是同一套设置

### 已完成 · 稳定性与工程化

- 配置持久化根治：原子写 + 失败自动回退 + 保存结果可查（设置页「最近一次保存」）
- 运行日志落盘（轮转 + 未捕获异常钩子 + 关键操作留痕）
- 界面黑屏兜底：页面级错误边界 + WebView2 关闭 GPU 合成
- 局域网放行一键配置（覆盖手机控制台 / 临时传输 / 机房 / 发现端口）
- **版本号单一来源**：`version.json` + `scripts/sync_version.py`，打包前自动同步
- **sigstore 无密钥签名**：发布包可由用户一条命令验证来源（`.github/workflows/sign-release.yml`）
- **SignPath Foundation 申请材料就绪**（见 `SIGNING.md`）
- 打包卫生：旧产物只保留最近 2 份；安装包排除运行时数据；启动自检

## 三、方向定案（2026-10）

经过一轮战略讨论定下三条主线。**明确不做**：全自动远程还原（还原卡/冰点/Clonezilla 的主场，
失败责任在千元级）、EDR 与网络隔离（安全厂商与 Windows Defender 的主场，单机软件也做不到
"学生关不掉"）、AI 寿命预测（几十台的样本量不足以支撑模型，宣称"还剩 45 天"一旦不准，
信任是一次性的）。

1. **现场闭环做顺**：体检 → 一键修复 → 还原保护检测 → 报告 → 经验沉淀。
   老师端只给「正常 / 建议修复 / 请报修」，技术细节折叠进「查看详情」。
2. **衰退监测与维护清单**（"预测"的诚实版）：只用**可解释的数值**
   （读写错误计数、温度、通电时间、异常关机次数、磁盘空间）出「该换谁的硬盘 / 该给谁清灰」。
   ✅ 首版已完成（维护 → 维护清单）
3. **与还原保护协同，不替代还原卡**：还原保护状态检测、黄金配置模板（`.ocbprofile`）、
   IT 到场的急救工具（引导修复 / 系统盘备份恢复 / USB 急救盘）。

**商业模式**：软件保持免费开源，靠部署、定制与技术支持收费 —— 不做功能分层锁
（MIT 协议下功能锁没有意义，且会劝退学校）。

### 本轮新增（方向落地）

- **维护清单（衰退监测）首版** `core/health_watch.py` + 维护页分区：
  磁盘可靠性计数、异常关机/蓝屏（事件 41/6008/1001）、CPU 温度、磁盘空间；
  SMART 读不到时**如实告知**（需管理员权限）并降级到"健康状态 + 空间 + 事件"，绝不编数
- 安全与可解释性：`docs/SECURITY.md`（威胁模型 + 7 条审查结论）、诊断包脱敏、慢调用告警
- 体验：渲染模式可切换（GPU 合成开关）、定时任务失败弹托盘通知、UI 切换与交互动画
- **配置自动备份与历史** `core/config_backup.py`：每天启动自动留一份快照（当天去重）、
  保留最近 30 份、恢复前先存「恢复前快照」可反悔；只备份配置本身，不含日志/缓存/插件
- **统一诊断结果模型** `core/diag_result.py`：体检 / 课堂检测 / 维护清单三套形状归一，
  一份结果同时供界面卡片、报修报告与远程汇总使用；状态五档文案与维护清单**逐字一致**
  （一致性断言防漂移）；只有确实有修复动作的项才给「修复」按钮，修不了的标 `manual`
  明说"这事得人工" —— 点不动的按钮比没有更让人恼火
- **课前准备** `core/preflight.py`：体检 + 课堂 + 还原保护串成一条流程，并**替老师做判断**。
  结论三档（可以上课 / 有建议看一眼 / 建议先处理）。只有网络断、无显示设备、无音频设备
  才算「卡课」；投影还没接、触摸不灵、还原被停只算"有影响" —— 老师常常是"先凑合上完
  这节课"，一律报红只会让人学会无视这个灯
- 报修报告升级：诊断结论与「需要处理」置顶、区分物理/虚拟网卡；体检页可**生成完整报告**
  并一键复制（老师报修用的是微信/钉钉，要的是能直接粘过去的一段话）
- **临时传输并入手机控制台**：原先是独立的 38620 服务 + 独立房间码 + 独立页面，
  要记两个码、开两个地方；现在**一个端口（38610）、一个访问码**，聊天从界面移除
  （后端接口保留）。代价是**权限统一** —— 能管这台机器的人就能往它传文件，
  这是有意接受的取舍。手机打开控制台即可传文件，电脑之间互传也走同一条路。
  接收开关只有本机能开/关，且判断依据是本机**全部** IPv4 地址（多网卡时
  只跟 `local_ip()` 那一个比，会把「从另一个地址访问自己」误判成局域网设备）。
  上传全程流式（前后端都不把文件读进内存）—— 200 MB 上限下这是「卡住没反应」
  的根源。

## 四、计划

### P0 —— 可发布性与稳定性

1. **自动化测试（pytest）**：优先覆盖
   - `core/paths.py`：便携模式、受保护目录回退
   - `core/config.py`：迁移、损坏配置恢复、写入失败回退
   - `core/registry.py`：工具扫描、入口选择、异常 `tool.json`
   - `core/market.py`：sha256 校验、路径穿越、解压总量限制
   - `net/proto.py` / `net/server.py`：非法请求、断线、重复节点
   - `core/repair.py` / `core/restore.py`：提权失败与取消（**只验证命令构造，不实际执行**）
2. **Windows CI**：`windows-latest` 上跑依赖安装 → 前端构建 → `smoke.py` → PyInstaller 打包，
   确保"主分支随时可打包"；后续再加安装/卸载/升级的自动化。
3. **拆分 `backend/api.py`**：按领域拆成 `system / network / plugins / security / tasks / media`，
   保留一个薄的兼容层，避免一次性改动前端调用协议。

### P1 —— 把"课堂急救箱"做成核心体验

4. ✅ **体检与修复流程化**：已落地为「课前准备」（维护 → 课堂）—— 结论三档，
   可修项一键修复后**自动复查**；老师端只给结论，`manual` 项明说该找谁。
   待办：把「正常 / 建议修复 / 请报修」这三个词显式贯穿到远程与手机端。
5. ✅ **统一诊断结果模型**：`core/diag_result.py`，已接入体检 / 课堂检测 / 维护清单 /
   报修报告。待办：前端三个页面切到统一渲染、远程批量检查与手机端接同一形状。
6. **报修报告增强**：软件版本与来源、Windows 版本与设备型号、驱动摘要、最近体检、错误日志、
   网络诊断摘要、服务/防火墙状态；**明确过滤个人信息**（用户名、含姓名的路径）。
7. **安全边界文档化**：为 `remote_admin.py` / `webconsole.py` / `chat.py` / `net/server.py`
   写威胁模型，并补对应测试；把"动作白名单、二次确认、审计、默认内网来源、文件名清洗"
   固化成代码级约束。

### P2 —— 生态与工程一致性

8. **插件协议版本化**：`tool.json` 增加 `manifestVersion` / `permissions` / `minAppVersion` /
   `publisher` / `license`；安装前展示权限；市场增加索引签名、版本锁定与回滚、失效插件禁用。
9. **安装包与运行时**：评估用微软官方 Fixed Version Runtime 替代内嵌运行时（许可更明确）；

10. **发布流水线**：一次生成安装包 + 便携 ZIP + `SHA256SUMS` + sigstore bundle + 组件清单 + 更新日志。

## 五、产品原则

1. **离线优先**：检测与修复不依赖外网；联网功能必须可降级并说明原因
2. **免依赖**：目标机无需安装任何前置组件
3. **一键化 + 结论化**：面向老师的功能只暴露「一个按钮 + 一句结论」
4. **危险操作可回滚**：清理 / 重置 / 电源类操作先备份、二次确认、可恢复、有审计
5. **如实反馈**：拿不到的数据显示"不可用"，失败给出可读原因，绝不编造
6. **不碰红线**：不内置任何绕过授权、破解、隐私窃取类功能
